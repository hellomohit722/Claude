# Claude Mastery --- Day 1 Notes

## 1. What is Claude?

Claude is a family of large language models (LLMs) developed by
**Anthropic**.

At a high level, Claude takes input such as instructions and context,
processes that information as tokens, and generates an output token by
token based on patterns learned during training and the context
provided.

### Basic flow

``` text
Input
  ↓
Instructions + Context
  ↓
Tokens
  ↓
Claude / LLM
  ↓
Generated tokens
  ↓
Output
```

------------------------------------------------------------------------

## 2. What is an LLM?

**LLM = Large Language Model**

An LLM is a machine-learning model trained on very large amounts of data
so that it can understand and generate natural language and, depending
on the model, work with code and other modalities.

Examples of LLM families include:

-   Claude --- Anthropic
-   GPT --- OpenAI
-   Gemini --- Google

### Important idea

An LLM is not simply a traditional database that looks up an answer. It
generates responses based on learned patterns, the instructions it
receives, and the context available to it.

------------------------------------------------------------------------

## 3. What is a Token?

A **token** is a unit of text processed by an LLM.

A token can be:

-   Part of a word
-   A complete word
-   Punctuation
-   Whitespace-related text fragments

For example, conceptually:

``` text
"ThreadLocal is useful"
        ↓
["Thread", "Local", " is", " useful"]
```

> The exact tokenization depends on the tokenizer and should not be
> assumed from this simplified example.

### Why are tokens important?

Tokens affect several important aspects of AI applications:

-   **Context** --- how much information can fit into the model's
    context
-   **Cost** --- API usage is commonly measured partly through token
    usage
-   **Latency** --- more input/output can increase processing time
-   **Input/output limits** --- models have limits on how much text they
    can process or generate

------------------------------------------------------------------------

## 4. What is a Context Window?

A **context window** is the amount of information a model can consider
within a single request/conversation context.

It can contain things such as:

-   System instructions
-   Conversation history
-   User's latest request
-   Documents
-   Source code
-   Tool results
-   Other relevant context

### Conceptual representation

``` text
┌──────────────────────────────────────┐
│           CONTEXT WINDOW             │
│                                      │
│ System instructions                  │
│ Conversation                         │
│ Documents                            │
│ Source code                          │
│ Tool results                         │
│ Latest request                       │
│                                      │
└──────────────────────────────────────┘
                    ↓
                  Claude
                    ↓
                Response
```

### Why does context matter?

The model's ability to reason about a task depends heavily on the
information available in its context.

If the required information is missing, incomplete, poorly structured,
or exceeds practical context limits, the quality of the response can
suffer.

### Important distinction

It is better to say:

> "The relevant context needs to fit within the model's available
> context window."

rather than:

> "If context exceeds the context window, we do not get the perfect
> result."

A model cannot process information that is outside the context available
to it for that request.

# 5. Prompt ≠ Just a Question

A beginner may write:

``` text
Write Selenium tests.
```

A more effective prompt can provide structure:

``` text
ROLE
You are a senior QA automation engineer.

CONTEXT
We are testing a Spring Boot application.

TASK
Generate Selenium test cases for the login workflow.

CONSTRAINTS
- Java
- Selenium WebDriver
- TestNG
- Page Object Model
- Include positive and negative scenarios

OUTPUT
Return a table containing:
Test ID
Scenario
Steps
Expected Result
Priority
```

A structured prompt gives the model more useful information about what
you want.

### Benefits

It can:

-   Reduce ambiguity
-   Reduce unnecessary assumptions
-   Make the output more consistent
-   Improve task adherence
-   Make the response easier to evaluate

However, **structured prompting does not guarantee that hallucinations
will disappear**. Hallucinations can still happen, so verification and
evaluation remain important.

# 6. Normal Chatbot vs Agentic Workflow

## Normal chatbot

A simple chatbot interaction can look like:

``` text
User
  ↓
Question
  ↓
LLM
  ↓
Answer
```

The model primarily generates a response to the user's request.

## Agentic workflow

An agentic system can go further:

``` text
User Goal
    ↓
   Agent
    ↓
Understand task
    ↓
Plan
    ↓
Use tool
    ↓
Observe result
    ↓
Reason
    ↓
Use another tool
    ↓
Verify
    ↓
Final result
```

An agent can be designed to use tools and perform multiple steps toward
a goal.

### Example

Suppose you ask:

``` text
"Find why my Selenium test is failing and fix it."
```

A basic chatbot might explain possible causes.

An agentic coding workflow could:

``` text
Read repository
      ↓
Inspect test
      ↓
Inspect application code
      ↓
Run tests
      ↓
Analyze failure
      ↓
Modify code
      ↓
Run tests again
      ↓
Verify fix
```

This is why **agents and Claude Code** will become important later in
this course.

# 8. Day 1 Quiz --- My Answers

## Q1. What is Claude?

Claude is a family of LLMs developed by Anthropic. It processes
instructions and context and generates responses based on learned
patterns and the context provided.

## Q2. What is an LLM?

LLM stands for **Large Language Model**. It is a machine-learning model
trained on large amounts of data to understand and generate language
and, depending on the model, code and other types of content.

## Q3. What is a token?

A token is a unit of text processed by an LLM. It can represent part of
a word, a complete word, punctuation, or other text fragments depending
on the tokenizer.

## Q4. What is a context window?

A context window is the amount of information a model can consider
within a particular request or conversation context.

It can contain instructions, conversation history, documents, code, tool
results, and the latest request.

## Q5. Why does context matter when working with large codebases?

Large codebases contain a lot of information. The model needs relevant
code, requirements, error messages, and other context to reason
effectively.

The available context must fit within the model's context window.
Managing and selecting relevant context becomes especially important
when working with large repositories.

## Q6. What is the difference between a simple prompt and a structured prompt?

A simple prompt may leave important details unspecified.

A structured prompt can provide:

``` text
Role
↓
Context
↓
Task
↓
Constraints
↓
Output Format
```

This reduces ambiguity and makes it easier for the model to follow the
intended task.

## Q7. What is the difference between a normal chatbot workflow and an agentic workflow?

A basic chatbot primarily generates a response to a user's request.

An agentic workflow can pursue a goal through multiple steps,
potentially using tools, observing results, reasoning about those
results, taking additional actions, and verifying the final result.

# 11. Day 1 Practical Exercise

Use Claude and try this prompt:

``` text
You are a senior Java engineer and teacher.

I am learning Java ThreadLocal.

Explain ThreadLocal to me in three levels:

Level 1:
Explain it to a complete beginner.

Level 2:
Explain how ThreadLocal works internally.

Level 3:
Explain how ThreadLocal is used in real-world
Spring Boot applications.

Then provide:

1. A simple Java example
2. A Spring Boot example
3. Common mistakes
4. 5 interview questions

Do not skip the internal working.
```

Then ask:

``` text
Now challenge my understanding.

Give me 5 questions about ThreadLocal,
one at a time.

Do not reveal the answer until I respond.
```

The goal is to practice using Claude as a **learning and reasoning
partner**, not just as a question-answering tool.
